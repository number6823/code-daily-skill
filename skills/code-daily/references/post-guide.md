## 1. 기본 템플릿

기본 출력은 **노션과 Velog 둘 다에 그대로 붙여넣을 수 있는 공통 마크다운**이다.
제목 단계는 `#` `##` `###` 세 단계까지만 쓴다 (노션 제목 블록이 3단계뿐이라 `####` 는 일반 텍스트가 된다).

````markdown
# {날짜} {주제} — {한 줄로 무엇을 했는지}

> 💡 **한 줄 요약**: {이 실습/코드가 해결하는 문제와 방법을 한 문장으로}

## 1. 오늘 만든 것
- 목표: {왜 이걸 만들었는지}
- 사용 기술: {라이브러리, 버전}
- 결과: {무엇이 동작하게 되었는지}

## 2. 전체 구조

```text
{폴더명}/
├── app.py      # UI
└── auth.py     # 인증 로직
```

| 함수 | 입력 | 출력 | 설명 |
|---|---|---|---|
| `login` | `username: str, password: str` | `bool` | 아이디·비밀번호가 맞으면 True 를 반환한다. |

**흐름**: 입력 폼 → `register()` → `hash_password()` → DB 저장

## 3. 핵심 코드 살펴보기

```python
{발췌 코드 10~30줄}
```

- **무엇을**: {이 코드가 하는 일}
- **왜 이렇게**: {다른 방법 대신 이 방법을 쓴 이유}

### 3-2. ...

```

{실행 결과 — 사용자가 준 출력/스크린샷이 있을 때만. 없으면 아래 주석을 남긴다}
<!-- 📸 실행 화면 캡처 넣기 -->

## 5. 배운 점 / 막혔던 부분
- {개념이나 함정. 코드에서 근거를 찾을 수 있는 것만}

## 6. 다음에 해볼 것
- {코드의 TODO, 미구현 부분, 개선 아이디어}

---
🏷️ #Python #{라이브러리} #{주제}
````

### 섹션 작성 요령

- **제목의 날짜**: 폴더명이 `261023_15_claude` 처럼 `YYMMDD` 로 시작하면 그 날짜(`2026.10.23`)를 쓴다. 없으면 오늘 날짜.
- **2. 전체 구조**의 함수표는 `outline.py` 출력을 그대로 가져오되, 독자에게 의미 없는 내부 함수(`_` 시작)는 빼도 된다. 타입이 `?` 인 칸은 코드를 읽고 추론해서 채우고, 추론한 값이라는 걸 본인은 알고 있되 글에는 자연스럽게 쓴다.
- **3. 핵심 코드**는 파일 전체를 붙이지 않는다. 독자가 기억해야 할 지점 2~4개만 발췌한다. 긴 코드 전문이 필요하면 맨 끝에 "전체 코드" 섹션을 따로 둔다.
- **5. 배운 점**은 코드 속 "왜" 주석, 보안 처리(`hmac.compare_digest` 등), 타입 선택 이유가 좋은 재료다.
- **6. 다음에 해볼 것**에는 `outline.py` 가 찾아준 `TODO` 를 쓴다.

## 2. 게시처별 차이

### 노션
| 요소 | 붙여넣었을 때 |
|---|---|
| `#`~`###` | 제목 1~3 블록 |
| ` ```python ` | 언어가 지정된 코드 블록 |
| 표 | 단순 표 블록 |
| `> ` | 인용 블록 (`> 💡` 로 시작하면 콜아웃처럼 보인다) |
| `---` | 구분선 |
| 로컬 이미지 경로 | **업로드되지 않는다** → `<!-- 📸 -->` 주석으로 자리만 표시 |
| `<details>` 등 HTML | 지원 안 됨 → 쓰지 않는다 |

### Velog
- 순수 마크다운 그대로 붙여넣으면 된다. front matter 는 쓰지 않는다.
- 태그·시리즈·썸네일은 출간 화면에서 따로 입력하므로, 글 끝에 `🏷️` 줄로 추천 태그만 적어준다.

### GitHub 블로그 (Jekyll / GitHub Pages)
사용자가 GitHub 블로그용이라고 하면 아래를 추가한다.

1. 맨 위에 YAML front matter:
   ```yaml
   ---
   layout: post
   title: "{제목}"
   date: 2026-10-23
   categories: [Python]
   tags: [streamlit, auth]
   ---
   ```
   이때 본문의 `# 제목` 줄은 지운다 (테마가 title 로 제목을 이미 그린다).
2. 파일명은 `YYYY-MM-DD-영문-슬러그.md` (Jekyll `_posts/` 규칙).
3. 코드 블록 안에 `{{` `}}` 나 `{%` 가 있으면 Jekyll 의 Liquid 가 해석해버려 글이 깨진다. 그런 코드 블록은 `{% raw %}` … `{% endraw %}` 로 감싼다.
4. 🏷️ 태그 줄은 front matter 의 `tags` 로 옮겼으니 지운다.

## 3. 공개 전 점검

블로그는 공개되는 글이다. 저장하기 전에 아래를 꼭 확인하고, 바꾼 게 있으면 사용자에게 알려준다.

- **API 키·토큰·비밀번호**: `sk-...`, `hf_...`, `AKIA...`, `.env` 값, 하드코딩된 비밀번호 → `"<YOUR_API_KEY>"` 로 바꾼다.
- **개인 경로**: `C:\Users\{이름}\...`, `/home/{이름}/...` → `~/...` 또는 프로젝트 기준 상대경로.
- **이메일·실명·내부 URL** → 지우거나 일반화.
- **DB·가중치 파일 내용**: `users.db` 안의 데이터, `.pt` 파일 경로 등은 글에 넣지 않는다.
